HOW THE PROGRAM RUNTIME WORKS:
---------------------------------------------------------
I am going to explain to you how the programs run, but i will
	explain how to program it after i explain how the programs
	are ran.
	When you run a program, the CPU runtime chip will send
	information to CELL 0 in the memory card. After the CPU
	tries to send the data to the memory card, it will see
	if the data was really sent to the memory.
	If the CPU sees that the memory was not successfully sent,
	then the CPU will generate an ERRORCODE. When an error occurs,
	the error light on the front of the case will turn red. When
	and error does occur, you will have to reset the CPU, which
	is done through the interface.
	IF the CPU sees that the information was successfully sent to
	to the Memory card, then it tries to run the program inside
	memory. The code in the memory is all numerical.
	Now i talk about how a program is ran.
	When the CPU first runs the program, it starts at cell one.
	So you cannot have a program start at cell 2. The CPU always
	starts program runtime from CELL 1.
	When the CPU runs a command, the CPU will also read the series
	of arguments. The command arguments, tell the CPU how the command
	is going to be ran.
	For example:
	if the CPU starts at cell 1 and then runs a command that takes 3
	arguments, then the command ends at cell 4
		CELL 1 | CELL 2 | CELL 3 | CELL 4 |
	   command   arg1      arg2     arg4
	   -----------------------------------
	 After the CPU runs a command, the CPU will try to run the next
	 command RIGHT after the cell of the last agument of the previous
	 command. So you cannot leave a space between a command or else the
	 CPU go into a continuous loop and keep checking if there is a command
	 in the cell when there is not. When this happens and the CPU keeps
	 running, you just enter the stop command into the interface.
	 You should always put the terminate command at the end of your
	 program also to successfully terminate the program.
	 The only way you can have gaps in the program code is when you use
	 the goto command or any of the if/else commands.
	 Here is a quick example of how the order of commands should be written.
	 
	 Cell | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
	 code |cmd|arg|arg|arg|cmd|arg|arg|-1 | 0 |
		See how there is no gap between cell 4 and 5?
		Thats how the order is supposed to be.
		The -1 in cell 8 is the terminate command and that
		command is also right after the last argument of the previous command.
		
	Here is the WRONG WAY:
	 Cell | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
	 code |cmd|arg|arg| 0 |cmd|arg|arg|-1 | 0 |
		The problem in this is that there is a gap between 3 and 5.
	
	I have already told you that there is only 2 ways you can have gaps in your
	code.
		1st way:
			You can use the GOTO command to go to a certain cell, but you got to
			make sure you do it right because if you use the goto command to goto
			cell that contains one of the arguments of a command then your program
			will FAIL.
			Here is an example of how the goto command works:
				Cell | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
				code |cmd|arg|arg| 0 |cmd|arg|arg| 2 | 1 |
					The goto command is at cell 8 and the 1st argument for the command
					is right after the command, which is one.
					This command tells the CPU to go to cell 1.
					The program will end up creating an infinite loop, making the user
					have to run the stop command to terminate the program.
					loops are very useful in programming.
					If i would have changed the goto command to
					make the CPU go to cell 3 then that would cause a fail because
					your not supposed to goto a cell containing a commands arguments.
					THIS stuff about the goto command also applies with the IF/ELSE
					commands because if the statement returns FALSE then it will go
					to the specified cell and if it is true then it will go to the
					other specified cell.
					Well that is just about all you need to know about how the program
					runs. I am now going to explain how to use the interface commands and after
					that i am going to show you the program command list.
					
HOW TO USE THE INTERFACE:
----------------------------------------------------------
using the interface is pretty simple, its just the programming
that messes you up because when you write a program you have to make
sure that you know what you are coding or else if you make a mistake
then you have to change everything and shift all the cells and everything.
anyways, i am going to tell you how to use the interface and use write, read and
delete command.

Command List:
	1. run
		-Runs the program in the memory
	2. stop
		-stops a program that has not ended
	3. reset
		-Resets the CPU if and ONLY IF the cpu has had a
		runtime error. The interface will also display the
		error code when you reset the CPU.
	4. w
		-This is the write command and this command
		contains 2 arguments. The first argument is
		the value being sent to the specified cell and
		the second argument specifies what cell to throw
		the value into.
			EX:
				w 100 5
				(write 100 to cell 5)
	4. r
		-This is the read command, which allows the user
		to view data in the cell specified.
			EX:
				r 1
				(read value in cell 1)
		Another way to use the read command is the list
		method which lets you view a list of cells.
			EX:
				r 10 - 20
				(lists cells 10 to 20 )
			A thing you need to know about the read list method
			is that if you try to view too many cells, the list of all
			the cells wont fit on the screen. So you should view a maximum 
			of like 12 cells
	5. d
		-This is the delete command and it allows the user to delete
		specified cells. This command also uses the list method so you
		can delete more than one cell at a time.
			EX:
				d 50
				(delete cell 50)
			EX:(list method)
				d 10 - 43
				(deletes cells 10, 43 and the cells between those
				2 values)
		-you cannot delete cell 0 because it is system memory.
		-You can cannot delete cells under 0 because there is no
		such memory.
	6. cls
		-this the CLEAR SCREEN command and you use this command
		to clear your screen and use it if you are writing data
		and your screen fills up with text.
Well that all the commands that the interface has,

PROGRAM COMMAND LIST:

1. OUTPUT COMMAND:
	cmd: 1 
		arg1: (1 or 2) //Specify where data is being outputted to
			1 = OUTPUT
			2 = REGISTER
		arg2: (1 - 5) //Specify which port to output the data to
						There are five registers and Outputs.
		arg3: (1 - 3) //Specify Source type(where data is coming from)
			1 = INPUT
			2 = REGISTER
			3 = USER DEFINED
		arg4:
			if(arg3 = 1) then arg4 = 1-5 // Specifies which input port
											to retrieve data from
			if(arg3 = 2) then arg4 = 1-5 // Specifies which register
											to retrieve data from
			if(arg3 = 3) then arg4 = any value
	EXAMPLE:
		1 2 1 3 1000
		(send value of 1000 to the first register)

2. GOTO COMMAND:
	cmd: 2
		arg1: (#) // Specify which cell to goto.
	EXAMPLE:
		2 100
		(goto cell 100)
		
3. TERMINATE PROGRAM COMMAND
	cmd: -1
		(no arguments required)
		
4. MATHEMATICS COMMAND:
	cmd: 5
		arg1: (1-4)
			1 = ADDITION
			2 = SUBTRACTION
			3 = MULTIPLICATION
			4 = DIVISION
		arg2: (1 - 2) //Specify where to output the answer to
		arg3: (1 - 5) //Specify which port to out the answer to
		arg4: (1 - 3) //Specify the source of value 1
			1 = INPUT
			2 = REGISTER
			3 = USER DEFINED
		arg5:
			if(arg4 = 1) then arg5 = 1-5 // Specifies which input port to
											get the value from
			if(arg4 = 2) then arg5 = 1-5 // Specifies which register
											to get the value from
			if(arg4 = 3) then arg5 = any value
		arg6: (1 - 3) //Specify the source of value 2
			1 = INPUT
			2 = REGISTER
			3 = USER DEFINED
		arg7: 
			if(arg6 = 1) then arg7 = 1-5 // Specifies which input port to
											get the value from
			if(arg6 = 2) then arg7 = 1-5 // Specifies which register
											to get the value from
			if(arg6 = 3) then arg7 = any value
	EXAMPLE:
	5 2 1 1 3 100 3 50
		(subtract 50 from 100 and send the result to output port 1)

5. LOGIC TESTER COMMAND
	cmd: 10
		arg1: (1 - 5) //Specify logic type
			1 = IF EQUAL
			2 = IF NOT EQUAL
			3 = IF GREATER THAN
			4 = IF LESS THAN
			5 = IF GREATER THAN OR EQUAL TO
			6 = IF LESS THAN OR EQUAL TO
		arg2:(1 - 3) //Specify source of value being tested
			1 = INPUT
			2 = REGISTER
			3 = USER DEFINED
		arg3:
			if(arg2 = 1) then arg3 = 1-5 // Specifies which input port to
											get the value from
			if(arg2 = 2) then arg3 = 1-5 // Specifies which register
											to get the value from
			if(arg2 = 3) then arg3 = any value
		arg4: (1 - 3) //Comparing the source of this value to the other value
			1 = INPUT
			2 = REGISTER
			3 = USER DEFINED
		arg5:
			if(arg4 = 1) then arg5 = 1-5 // Specifies which input port to
											get the value from
			if(arg4 = 2) then arg5 = 1-5 // Specifies which register
											to get the value from
			if(arg4 = 3) then arg5 = any value
		arg6: //IF STATEMENT IS TRUE THEN GO TO SPECIFIED CELL (should not equal 0)
		arg7: //IF STATEMENT IS FALSE THEN GO TO SPECIFIED CELL (should not equal 0)
		
		EXAMPLE:
			10 2 3 100 3 200 10 20
			(if 100 is NOT equal to 200, then goto cell 10; ELSE: goto cell 20)
